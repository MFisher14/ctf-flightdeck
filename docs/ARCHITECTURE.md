# Architecture (draft)

## Pipeline

```
pull → triage → unpack → L1 → assign → agents → verify → submit → record
```

Every stage has a **policy**: `auto` (harness does it), `confirm` (harness prepares it, player presses a
key), `manual` (harness tells the player what to do), `off`. Pre-flight sets policies from the event
profile and rules and refuses configs that would break a rule (no platform API → pull/submit manual; no
AI → agents off; no automation against live targets → instance access confirm or off).

## Components

| Component | Job |
|---|---|
| Platform adapter | Board, challenge download, submit. `manual` (folder) first, then `ctfd`. |
| Triage | Category, points, solves, hints in the description; decides order and lane settings. Rules, not a model. |
| Unpack | Recursive archive extraction into a scratch copy, with depth/size limits and zip-slip protection. |
| L1 runner | Routes a challenge to the player's no-model solvers, runs them sandboxed in parallel, collects `SolverResult`s. Results seed the agent lane's starting state. |
| Lane manager | Starts, queues (`max_lanes`), pauses, forks, kills lanes; Docker or host per `containerized`. |
| Agent drivers | One interface: flightdeck's own lean loop over a model API (M1), the `claude`/`codex` CLIs as subprocesses (M2). ACP agents later. |
| Interventions | Hint, redirect, fork, escalate, take over, approve; all recorded in the event log. |
| Detectors | Produce alerts from lane activity (see CONSOLE-SPEC). |
| Budget meter | Tokens, turns, dollars per lane and in total; enforces caps. |
| Event log | Append-only JSONL of everything; feeds post-flight. |
| Console | Textual UI over all of the above. |

## The console seam (built in M0)

The console never talks to lanes directly. It reads a `Deck` and sends it interventions:

| Piece | Where | Job |
|---|---|---|
| Data model | `core/model.py` | `Challenge` (with the tries its platform allows: `max_attempts`, `tries_left`, `limited`), `Lane` (state, counters, plan, a log of actions that is its transcript, artifacts, changed files, alerts, approvals; known and unknown dollars, a CLI turn's cost still to come), `Alert` with `Suggestion`s, `EscalationSummary`, `Event`, `DeckConfig`. |
| `Deck` | `core/deck.py` | Board, queue and lanes. Enforces `max_lanes` (paused and taken-over lanes keep their slot), the flag format and submit policy, a per-lane queue of approvals, 80%/100% caps, team-mode rules. Applies interventions and logs every change as an `Event` with a structured payload (the M1 JSONL log is the event stream). Must be called from one thread. A failure every lane would hit holds the queue (`hold_queue()`, a warning event with `held` true) until the player lifts it (`release_hold()`, the console's `/unhold`: refused when the queue is not held, logged as a warning with `held` false before the lanes it lets start; reports list both among the run's warnings). With a submitter (a platform over the network) a flag goes out without waiting for its answer, one at a time per challenge, and `platform_verdict()` applies the answer later, also after the lane ended or the challenge was solved meanwhile; `sending()` names a lane's flags on their way. A flag on its way that goes back to the player (no verdict, or the platform counts the tries) waits as an approval on each lane that sent it and is still at work; a lane that gave up on it ends, unless no lane at work sent it. A challenge whose tries the platform counts (`Challenge.limited`) never gets a flag without the player, and a flag the player approved keeps its turn after a count of tries unless it would spend the last one. `Deck.report` applies a spend-only report (`spend_only`: tokens, cached tokens or dollars, and nothing else) to a lane that has ended: it counts for the lane and the run, is logged as a spend event with the model that spent it and why, and the lane's transcript is written again; no cap is asked about, and anything else in a late report is dropped. |
| Interventions | `core/interventions.py` | `Pause`, `Resume`, `Hint`, `Redirect`, `Fork`, `Kill`, `Escalate`, `TakeOver`, `HandBack`, `Approve`, `Claim`, `Release`, `Queue`, applied with `Deck.apply()` → `Outcome`. |
| `LaneDriver` | `core/driver.py` | What does a lane's work. The deck calls `start/pause/resume/hint/redirect/escalate/approved/rejected/stop`; the driver answers each step with `Deck.report(lane_id, TurnReport)`. It starts a turn only while the lane is RUNNING. `TurnReport.dollars_later` marks a coding-agent CLI's step, whose cost comes with the CLI's report at the turn's end (`turn_end`; with `unreported` and no dollars when it never came). A `Submitter` hands a flag to a platform over the network and returns at once. |
| Attention sort | `core/attention.py` | Needs you (most urgent first), informational, running by idle minute, paused; finished last. |
| Untrusted text | `text.py` | Everything from a challenge, lane, tool or model is drawn through `untrusted()` and never parsed as markup. |
| Console | `console/` | Route C (D16): `FleetScreen`, `FocusScreen`, the command bar and slash commands. Redraws on its own timer and on deck events, with or without a mock clock. Credits solves with `runrecord.Credit` over the deck's events, reading each once as the deck grows: the rule every report uses (an L1 engine's flag is `L1·<engine>`). `console/room.py` measures a terminal for `flightdeck doctor` with the console's own layout code (`fit_header`, `fleet.fit_keys`, `FLEET_ROWS`, `focus.key_room`). |

M0 plugs in `mock.script.ScriptedDriver` and a manual clock (`mock.world.FakeWorld`); M1 replaces them
with an agent loop per lane behind the same `LaneDriver` protocol.

## The working slice (built in M1)

| Piece | Where | Job |
|---|---|---|
| Folder board | `platform/manual.py` | A folder of challenge folders (format below); `answers.sha256.json` checks flags by hash; without it the player submits by hand and confirms (the deck's `CONFIRM` approval). |
| Config | `config.py` | `~/.config/ctf-flightdeck/config.toml`: the API (`provider` openai or anthropic, base URL, the name of the key's environment variable, never the key; with anthropic, `fast`: the ladder models called in fast mode; `timeout`: seconds per try of a lane's call; `max_tokens`: a lane's reply cap, which `lane_max_tokens()` makes 8192 (`LOCAL_MAX_TOKENS`) for an OpenAI-compatible server on this machine when unset, and leaves unset for any other) and an optional `[fallback]` API with its own ladder, timeout and max_tokens (no `fast`), the model ladder, prices (for a ladder model, or for a model of an `[agents]` ladder under the CLI's own name: codex reports no cost), lane defaults, the run folder, and an optional `[light]` light model (engine, model, base URL, key variable, timeout, price; the decider's confidence threshold; the openai engine's `thinking`, which `light_thinking()` makes false for a server on this machine when unset and true for any other). Unknown keys fail loudly. Keys are read from the environment, else `~/.config/ctf-flightdeck/keys.env` (`keys.py`, chmod 600). `flightdeck init` (`setup.py`) writes `timeout = 600` and `max_tokens = 8192` for a server on this machine, suggests a ladder for Ollama and MLX and a light model for `--light ollama|mlx` (from a benchmark on one machine; never written unless the player takes it), and writes `thinking = false` for a light model on this machine; `flightdeck doctor` names what lane calls to a server on this machine send and wait (`lane calls`). |
| Model client | `agent/client.py` | OpenAI-compatible chat completions over httpx; a stable `session_id` per lane for OpenRouter's sticky prompt caching; never `provider.order`; retries with backoff, each try bounded by the client's timeout (a lane's: `[api] timeout`, else 180 s); usage incl. cached tokens and the reported cost. A message key starting with `_` is flightdeck's own and never sent. Per client, `max_tokens` goes with every call that gives none (a lane's: `[api] max_tokens`, or 8192 to a server on this machine, nothing to another API), and `extra_body` adds a server's own fields to every request (the light role's thinking off); it may not set a field the client sets or never sends. |
| Anthropic client | `agent/anthropic_client.py` | `[api] provider = "anthropic"`: the Messages API through the official `anthropic` SDK, with the model client's interface. The driver's OpenAI-style history is translated each call: the system prompt is `system` with a cache breakpoint (tools and system are the fixed prefix), the tail is cached automatically, a reply's raw content blocks (thinking included) ride on its history message and go back unchanged, tool results become one user turn. No `thinking`, `temperature` or `tool_choice` is sent; Sonnet and Opus 5.5 carry the server-side refusal fallback, and a final refusal ends the lane as "the model declined (category)". Fast mode (`agent/fastmode.py`, facts from Anthropic's API documentation): a model in `[api] fast` is called with `speed: "fast"` (plus the fast-mode beta for a research preview) and priced at the fast rate unless `usage.speed` says standard; a 429 on a fast request is tried again at once at standard speed, and that lane session stays at standard speed (switching speed invalidates the prompt cache), with a notice on the lane. The SDK's own retries are off, so the driver's retry gate holds; the key and base URL are passed explicitly, never read from the environment by the SDK; no SDK exception is chained onto an error. Each try is bounded by `[api] timeout` (else 600 s), and a call that gives no `max_tokens` sends `[api] max_tokens` (else 16000). |
| Fallback | `agent/fallback.py` | Optional `[fallback]`: when the primary API fails for good with a retryable error (rate limit, 5xx, overload, no answer), the lane's call goes to the fallback API with the model at the same ladder position, and the lane stays there for the rest of its context (the APIs never mix in one context); the lane's transcript says so. Escalation and the context refresh try the primary again. A 400, 401 or refusal never moves a lane. Each API's client takes the timeout and max_tokens of its own table (`build_client()`). |
| Workspaces | `agent/workspace.py` | A copy of the handout per lane: on the host (an allowlisted environment, no keys) or in a container per lane (`--pull never`, with the run's labels); snapshots and diffs of the files a lane changes; the take-over shell, which reads no startup file (bash `--noprofile --norc`, in Docker too) and on the host gets a new owner-only HOME outside the workspace, removed at the hand-back or with the workspace (readline reads `~/.inputrc` whatever bash's flags say, and the player's own HOME would show a script the lane wrote the player's credentials). A host workspace notes the process groups it starts in the run's process record (`leftovers.py`). |
| Tools | `agent/tools.py` | `shell`, `read_file`, `python`, `http` (only the challenge's own origins), `submit_flag`, `set_plan`; long output cut, the rest saved to a file in the workspace. |
| Agent driver | `agent/driver.py`, `agent/prompts.py` | One asyncio task per lane on the console's loop (the deck's single thread). A turn is one model call; tool results go back into the context; the deck gets a `TurnReport` per turn. A small fixed prefix (the same text for every lane: nothing from the board), then the challenge brief (challenge text, the flag format among it, fenced as data). Escalation starts a fresh context with the deck's summary. Three replies in a row with no tool call end the lane (a flag written in one waits for the player); a model API failure every lane would hit (no answer, a refused key, an unknown model) holds the queue, saying why, before the lane ends. A flag the model submits that the challenge's description or handout, as it came, holds is not claimed: it waits for the player under auto too, and the model hears why; the lane says what that search of the handout left out (past 1 MB of a file, 16 MB in all, 5000 files, or 5 seconds). A lane that gives up while a flag of it still waits (for the player, or for the platform's answer) calls the model no more. |
| Run | `run.py`, `apicheck.py` | Checks config, board, key, Docker and the image before anything starts, then asks each model API once whether it takes the key and serves the ladder (a refused key, a model it does not serve or no server up stops the run); removes what runs whose flightdeck was killed left running (`leftovers.sweep`), records this run's (labels on its containers, `processes.json` in its folder), and notes the flag format it checks and where that came from; wires the deck, driver, event log and console; releases the board on the console's loop. A coding-agent run hands the driver every secret it holds to hide (`_held_secrets`: each keys-file value, the `[api]` and `[fallback]` keys, the CTFd token). |
| Event log | `eventlog.py` | Append-only `events.jsonl` per run: every deck event, flushed per line, with the value of anything shaped like a credential taken out (`credentials.py`); the flags the run has named, and the fields that name challenges, stay. Format 2 adds spend outside a turn as `spend` events; a coding-agent CLI's step is a turn event with dollars null and `dollars_later` true, and the CLI's report of the turn's cost a `spend` event with `turn_end` true (`unreported` true, dollars null, when it never came). Reports credit each spend event to its `data.model`. |

Board format: a folder; each subfolder with a `challenge.json` is a challenge:
`{"name", "category", "points", "solves"?, "description"?, "files"?, "urls"?, "id"?, "max_attempts"?}`
(unknown keys are an error; `urls` are the live instances: http(s) origins, the http tool's, and
`tcp://host:port` services, which the shell reaches with nc; a CTFd pull reads both from the
connection info). `max_attempts` is how many tries the platform allows at the flag (0 or absent:
any number; a CTFd pull writes it), and that challenge's flags always wait for the player.
Optional `board.json`: `{"event", "flag_format"}`. Optional `answers.sha256.json`:
`{"<challenge id>": "<sha256 of the flag>"}`, outside the challenge folders.

What keeps challenge text from steering the harness is the harness, not the prompt: tools are fenced
to the workspace and the challenge's own URLs, the processes of flightdeck's own lanes are never
handed a key (a coding-agent CLI holds its own credential, which the commands it runs can read), a
flag reaches the platform only through the deck's approval (or the `auto` policy), a flag format is checked as
untrusted data wherever it is loaded (`flagformat.py`), and nothing a model writes changes a
setting.

## Agent loop principles (from measured experience)

These come from analysing about 300k agent responses across four 2026 CTFs:

- **Context size drives cost, not the model.** Most tokens are the same context re-read every turn.
  Keep each lane fresh per challenge, keep the fixed prefix small (target under 6K tokens), and
  truncate tool output (large outputs go to a file the agent can read on purpose).
- **A lane's own history grows too.** Past 50k prompt tokens (configurable) a lane continues in a
  fresh context: the same prefix and brief, so the provider's cache still hits, plus a summary of
  its work instead of every old tool output.
- **Long-lived orchestrator threads are the expensive tail.** The console is the orchestrator; it is
  code, not a model holding hundreds of thousands of tokens of context.
- **Caps and stop signals pay for themselves.** One stuck lane on one low-value challenge can cost more
  than the rest of an event. Per-lane caps, stall detection and teammate-solved stops are core.
- **Prompt caching must survive routing.** With OpenRouter, use a stable `session_id` per lane; setting
  `provider.order` disables sticky routing. With the Anthropic API, caching is by content: keep the
  system prompt and tools byte-identical and the history append-only within a context (that also keeps
  replayed thinking blocks valid).

## M2 to M4, and since

| Known-wrong flags | `core/deck.py` | A flag the platform rejected, or the player declined, is remembered per challenge: proposed again it raises no approval and is never submitted again, and an escalation's summary lists it. |

| Light role | `light.py`, `localmodel.py`, `localmodel_cli.py`, `needle.py` | The light model for small jobs, `[light]`: one interface (`Light`: name a technique, judge a lane, summarise one) on five engines, `rules` (the default, and every job's fallback), `openai` (an OpenAI-compatible server; recommended: an open-weight model on this machine, which costs $0; with `[light] thinking` false, the default for a server on this machine, each request asks for no thinking through the client's `extra_body`: `light.THINKING_OFF`, `reasoning_effort` "none", which Ollama reads, and `chat_template_kwargs` `enable_thinking` false, which mlx_lm.server reads), `anthropic` (effort low, room for thinking, no server-side refusal fallback), `cactus` (Cactus Needle, `needle.py`, in a thread of its own; `pip install "ctf-flightdeck[cactus]"`, telemetry off) and `decider` (a Strands Decider server, `DeciderLight`: each job one `choice` question in JSON with sorted keys, sent as application/json; untrusted text only in the state, which is sized in bytes to the 4,096-token window with the oldest steps left out first; the answer must name an option sent, with numbers in [0, 1] that agree; below the `[light]` threshold it is unsure and the rules' answer stands; one request at a time; $0 on this machine). | Post-flight | `postflight.py`, `writeup.py` | `flightdeck report RUN_DIR` (where lanes stalled, which interventions helped, cost per solve; each spend in the row of the model that spent it, a CLI's own turn costs apart from spend outside a turn) and `flightdeck writeups RUN_DIR` (a draft per solved challenge, from its transcript, with credentials taken out of every value it shows: `credentials.py`; both read an older run folder's log and transcripts cleaned the same way; it writes only in `RUN_DIR/writeups/`, so the run's own log and transcripts stay as they were written). |

| Credentials | `credentials.py`, `transcript.py` | The second redaction layer, after the first (the allowlisted environment, and a coding-agent lane's `[NAME]` for every secret the run holds): a lane's transcript (when it is written) and every value a writeup draft shows lose the value of anything shaped like a credential (an upper-case `NAME=value` or `NAME: value` naming a key, token, secret, password, cookie or auth, a Makefile's `:=` too; Authorization, Proxy-Authorization and Cookie header values; keys with a well-known prefix). The name stays and the value becomes `[redacted]`; the run's flags stay. Upper-case names only, since a lower-case key or password is everyday CTF content. | Leftovers | `leftovers.py` | The backstop for what outlives a killed flightdeck. `labels()` go on every container a run starts: the run, and the flightdeck that started it (a hash of the machine's id, the uid, the pid, its start time, and its state folder as a hash: `$XDG_STATE_HOME/ctf-flightdeck`, else `~/.local/state/ctf-flightdeck`). `ProcessRecord` keeps the run folder's `processes.json`: that flightdeck, whether the run used Docker, and its process groups on this machine with the processes seen in them and their start times, written atomically as they change; a note in the state folder's `open-runs/` names the run folder until the run ends cleanly, so the run is found wherever `--run-dir` put it. `sweep()` runs before each play or practice (and removes what it finds) and in doctor (which reports, and removes with `--clean`): it removes only containers with all of flightdeck's labels, of this machine, user and state folder, and a recorded group only while a recorded process with the same start time is in it and works under the run's folder. Its result says what it removed, what a clean sweep would remove, and what it leaves alone, with why. Start times and working folders come from /proc on Linux and the kernel (sysctl, proc_pidinfo) on macOS; elsewhere nothing is removed, and the sweep says why. |
| Model advice | `hardware.py`, `model_catalog.py`, `models.toml`, `models_cli.py`, `ollama_context.py` | `flightdeck models`. `hardware.py` reads the machine through an injectable `Host`: OS and architecture, the Mac's chip, total memory, NVIDIA GPUs (nvidia-smi, found only in PATH's absolute folders), the runtimes (Ollama's model list with sizes and the models it has loaded with the context it gives each, an MLX server's and LM Studio's, llama-server on PATH); each probe is short, needs no root and contacts only 127.0.0.1, and one that fails is unknown, with its reason. `model_catalog.py` loads `models.toml` (package data), refusing unknown keys, missing fields and duplicate ids: a local model has one build per runtime, each with its own `server_args` (MLX), `thinking` (the `[light] thinking` its light results were measured with, when not the default), `not_for` (the roles it is never offered for, and why), `measured` results (from `docs/MODELS.md`) and, measured job by job, a `jobs` table on the case set `[eval]` names: such a build is offered for each run job it did no worse at than a run with no light model (the judge and flagcheck right in a run as often; route and recon right as often as wrong), its light line is written from the figures, and its `[light]` lines set `jobs` to match; the Anthropic entry imports init's ladder and prices. What fits is an estimate: the weights plus 6 GiB of context for a lane or 2 GiB for the light role, against two thirds of unified memory on Apple Silicon, the largest NVIDIA GPU's memory, or else half the memory on the CPU; a missing size is "cannot tell". `--memory GB` (with `--apple` or `--gpu-memory GB`) gives the same advice for a machine described instead of this one, which is not probed. When the config's lanes use Ollama on this machine, it and `flightdeck doctor` (`lane context`, a warning) say what context Ollama gives the ladder's model (its `/api/ps` for a loaded one, else an estimate from `OLLAMA_CONTEXT_LENGTH` or the GPU memory: 4,096 under 23 GiB, 32,768 from 23, 262,144 from 47) against what a lane needs, and the fix; `[api] context` makes a lane's refresh point follow the server's context (`config.lane_refresh_at`). It recommends and never writes a config. `flightdeck doctor` shows the machine in one line that is never essential. |
