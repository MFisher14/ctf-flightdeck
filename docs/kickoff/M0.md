# Kickoff: M0 clickable mock

Paste this into a new agent session started in `~/ctf-flightdeck`.

```
You are starting milestone M0 of ctf-flightdeck. Read AGENTS.md, then docs/VISION.md,
docs/DECISIONS.md, docs/CONSOLE-SPEC.md and docs/ROADMAP.md (M0 section). Skim
docs/ARCHITECTURE.md. private-notes/ has local background; never copy it into tracked files.

FIRST: commit the scaffold that is already here as the initial commit on main (the
pre-commit secret guard must pass; never --no-verify). Then create branch m0 for all work.

GOAL: a clickable terminal mock of the flightdeck console, so the player can agree on
look and controls before anything real is wired. Fake, scripted data only: no models,
no network, no real challenges, no challenge binaries.

BUILD
1. Project: Python 3.12+, uv, src/ctf_flightdeck, Typer CLI `flightdeck` (plus a
   `ctfdeck` alias), Textual for the UI, pytest. Keep dependencies minimal.
2. `flightdeck mock [--scenario NAME] [--max-lanes N] [--team] [--host]` opens the
   console from CONSOLE-SPEC.md: header, board, scrolling lane list sorted by attention,
   detail pane, key bar.
3. A small fake-world model (board, challenges, lanes, events) driven by a scripted
   clock so lanes tick live: turns, tokens, dollars, last action, idle time, alerts.
   Design it so M1 can replace the fake driver with real lanes behind the same
   interfaces (lane state, events, interventions). Don't over-build: interfaces plus
   the fake implementation only.
4. Scenarios from CONSOLE-SPEC "Mock scenarios": wave drop (43 challenges, max_lanes
   16, queue), SSTV ignores-the-hint, overthinking a 50-pointer, web wrong way, team
   teammate-solved, flag found + approve submit. A default scenario combines them.
5. Every intervention key in the spec does something visible to the fake lane (hint
   and redirect take free text; take over shows a placeholder panel saying what M1
   will do). Every alert type fires at least once.
6. `flightdeck mock --screenshot DIR` runs the scenario headless and saves SVG
   screenshots of key moments (wave drop, an alert with its suggested action, the
   detail pane, team stop, approve submit).
7. Tests (Textual pilot): keys change lane state; attention sort puts alerts first;
   max_lanes is respected and the queue drains; team mode stops a lane when its
   challenge is solved by a teammate. Each test must fail if the behaviour breaks.
8. All demo challenge names and text are invented. No real event names, flags or
   player names.

RULES: follow AGENTS.md. Small commits on m0; do not push.

WHEN DONE: report what was built, how to run it, the screenshot paths, test results you
actually saw, and a list of design questions or spec changes you want the player to
decide. Then stop and wait for the player's review. Don't start M1.
```
